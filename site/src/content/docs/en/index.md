## Spec-first

The spec is born before the code and stays the truth after it — it's not
documentation written after the fact. Everything else (plan, dependency graph,
tests, quality gates) derives from the spec and is confronted against it. See
the [Spec](/en/docs/spec/) pillar for the full discipline.

## Two parts

**The doctrine** — the concept, tool-agnostic: the 6 pillars and the
common mechanism. These are the documents in this section.

**The CLI** — the Go tool that an AI operates to exercise the cycle. See
[The CLI](/en/docs/cli/).

## Where to start reading

1. [**Concept**](/en/docs/conceito/) — the foundation: the anchor, maturity, the
   graph, synchrony, issues. All the pillars presuppose it.
2. **The pillars**, in route order: [Structure](/en/docs/estrutura/) →
   [Planning](/en/docs/planejamento/) → [Spec](/en/docs/spec/) →
   [Traceability](/en/docs/rastreabilidade/) → [Propagation](/en/docs/propagacao/) →
   [Quality](/en/docs/qualidade/).
3. [**The CLI**](/en/docs/cli/) — the state of the tool, command by command.
