# v0.1.410

- **`anchors docs build` compiles a page whose `@anchors` header sits above its marker.** The compiler only writes a page that opens with its `anchors:generated` marker, so it never overwrites a page written by hand. The format 7 migration wrote the project's `@anchors` header at the top of every compiled page that carried a code. The marker was then no longer the first line, and the page read as handwritten. In MIF, 25 pages under `docs/` were reported as "NOT generated — they exist in `docs/` without the marker" and were not updated after 2026-10-04. The marker now counts when it follows an `@anchors` header (an HTML comment, or `#` lines in a YAML). The page is judged, compiled, pruned and staged by what follows the header, and the header is kept as it is. A page with a header and no marker is still treated as handwritten. Reported by MIF. (DTCDC-B25)

  Run `anchors docs build` once to bring such pages up to date.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
