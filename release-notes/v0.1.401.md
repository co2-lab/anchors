# v0.1.401

Two fixes in `anchors test`, both reported by MIF.

- **A stale test runs by default, whatever its last result.** The default selection left out stale test files whose last result had passed ("stale but passing", behind `--include-passing`). A stale result is no proof, and `evidence-fresh`, which blocks, refuses it. So the default run read green while the gate stayed red: MIF reached `evidence-fresh ✗578` with `anchors test` selecting 37 files. Every stale test file now runs by default. `--include-passing` now applies to mutation runs, where a stale score at the floor still waits for it. (SLCTN-B17)
- **A file handed to a suite that comes back with no result is named.** A suite whose `paths:` cover files its runner does not run (Maestro flows under a jest suite's `apps/mobile/**`) was handed them, proved nothing, and the run read as if they had run. The run now lists them as unproven and says how to fix it: narrow the suite's `paths:` to what its runner runs, and declare the suite that runs the others. (SLCTN-B18)

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
