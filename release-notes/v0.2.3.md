# v0.2.3

- **A product's changelog lies between its own tags, per branch.** With a `versioning:` block, `anchors changelog` reads a product's releases between its own tags, ordered by its scheme, each headed by the version its tag records (`1.10.0`, not `app-v1.10.0`); another product's tags do not split them. A branch rule takes `release: true` (its changelog lists the releases) and `changelog: true` (where `--write` writes); a branch that does not release lists the candidate, what came after the latest release, headed by the version its strategy computes. A product whose rules name no such branch releases, and writes, on every branch. `--product` and `--branch` pick them. (CLGCM, VRSNN)
- **A product declares its changelog outputs.** `versioning.<product>.changelog.outputs` lists files or directories, each with its `path`, `mode`, `template` and `format`; `--write` writes every one of them. A product with no outputs keeps the `changelog:` block. (VRSNN, CLGCM)
- **A stage that releases writes the tag and the GitHub Release.** A stage with `release: <product>` writes, once it passes and before its record, the product's tag on its sha with the version the sha carries, then the tag's Release with the changelog since the release before. A tag already on the sha is a rerun; on another sha, the same version was released twice, and the stage is recorded as failed. The workflow grants `contents: write`, and `pipeline-wired` diverges when it does not. (RLSTA, PCSPA, PWSPP)
- **New gate `changelog-valid`.** Declared with `scope: project`, it confronts every output, whoever wrote it: markers that read as versions, newest first, none twice, the unreleased block on top, a block for every tag and a tag for every block, and the block of a release unchanged against HEAD unless the commit message waives the gate. The output's `format:` adds the heading with its version and its tag's date, the `per_version` file names, required sections, no empty section, `max_chars`, and `required: changed` while the sources hold a version not released yet. (CHVLA)

With `versioning:` declared, `anchors changelog` now heads each release by its version rather than by its tag, and its markers name the version: a changelog file written before by tag names has its blocks written again. To use the new keys, install this binary first: an older one refuses them.
