## `dep-honored` names a flag whose kind contradicts its import

What reads the map trusts a `@dep` flag's kind: `section-required`'s `depends_on_layer`
counts only value dependencies. `dep-honored` now names two mismatches:
- `@dep:` on an import of types only. Write `@dep[type]:`.
- `@dep[type]:` on an import that runs. Write `@dep:`.

`anchors check --fix` already rewrote these flags; until now the gate let them pass.

The ts example's `type_import_pattern` now also reads braces whose every name is a type,
`import { type A, type B as C } from …`. If your project declares its own pattern, add the
second branch:

```yaml
type_import_pattern: '^\s*(?:import|export)\s+type\b|^\s*(?:import|export)\s*\{(?:\s*type\s+[\p{L}_$][\p{L}\p{N}_$]*(?:\s+as\s+[\p{L}_$][\p{L}\p{N}_$]*)?\s*,?)+\s*\}'
```

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
