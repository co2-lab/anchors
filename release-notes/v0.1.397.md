# v0.1.397

- **`required_states:` and the gate `states-required`: every spec of a layer registers the states the project requires of it.** A spec registers the states its author thought of, and every state gate confronts only those; MIF traced nine released defects to a screen state nobody wrote (an error shown as an empty list, a not-found that spun forever). The project names the states each layer owes, by the layer in the spec's header, and each spec of it registers a state by each name — a line carrying the state's code and the name — or waives it with `@no-state: <name> — <reason>`. The names are the project's; Anchors proposes none. Informative, in the catalog; asks nothing until `required_states:` is declared. (CNFGO-B78, STRQS)

  ```yaml
  required_states:
    screen: [loading, error, empty, offline]
  ```
