# v0.1.408

- **A spec whose codes are all proven again at its current revision reads fresh.** A spec's proof is only as fresh as its oldest contributing suite. Proofs ingested by hand, under reports no suite writes again (`out/fx.xml`, `t22.xml`…), therefore kept a spec stale forever. In MIF, 15 specs read "stale test signal (the spec changed since the ingestion — reingest)" after the unit suite had proven every one of their codes at the current revision, and no run could clear them. An old suite now holds the spec back only for codes it alone proves. A code that no suite has proven at the current revision still keeps the spec stale. Reported by MIF. (SGINA-B34)

  The fix applies to a spec's freshness when a suite that proves it is next ingested. A spec stuck this way clears with one run of its tests, for example `anchors test --changed <spec>`.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
