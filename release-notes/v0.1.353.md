## Fix: two monitors of one tree keep separate memories

Each `anchors monitor` now keeps its state in its own file: `.anchors/runs/monitor.<ANCHORS_SESSION>.json`.
With no `ANCHORS_SESSION`, the file is still `monitor.json`.

Two agents watching the same tree used to share one file. Their monitors overwrote each
other's state ("cannot write its state"). An event one monitor reported was also marked as
seen for the other, so that agent never heard it.

A watcher with a session starts with a fresh memory on its first run of this version. It
then says what is going on, once.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
