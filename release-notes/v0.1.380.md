## Fix: a spec's pieces are its unit's layer's, in every command

A spec names its unit's layer in its header (`layer: api-handler`), and the map derives the
unit's pieces by that layer: a `derived.overrides` entry with `when: api-handler` gives
`unit-complete` its `<op>_test.go`. The commands that derive the same pieces from a path used the
spec's own layer, `spec`, so they never read the override. At SS, `anchors work code --for
<op>.spec.md` prescribed `<op>.test.ts` for a Go handler.

`work`, `check --changed`, `deliver` and `watch` now derive a unit's pieces by the layer the
spec's header declares, as the map does. `work` names that layer next to the file's own
(`Unit layer: **api-handler**`).

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
