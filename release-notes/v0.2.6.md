# v0.2.6

- **The CI is the guarantee; the hooks are a convenience.** A commit made with the hooks pointed at `/dev/null` went in unconfronted, and nothing noticed. No mark a hook writes into a commit could prove it ran — whoever skips the hook can write the mark too —, so the Anchors promises none: the CI, running the same gates on every pull request and every push to a guarded branch, is what guarantees that nothing reaches a protected branch unconfronted, and the waiver in the commit message (`[skip-<gate>@<CODE>: <reason>]`) is the only way out of a gate on a commit. New doctrine rule SAIDA-R07; the quality page says where the gates run and which counts. (SAIDA)
- **`anchors doctor` warns when `core.hooksPath` points away from the Anchors hooks.** A `core.hooksPath` left in the configuration that points to a folder with no Anchors pre-commit, while the repository's own hooks folder holds the ones Anchors installed, is a warning `hooks-desviados` naming where it points; unset it, or install the hooks there. A one-off `git -c core.hooksPath=…` leaves nothing to read: the CI catches that commit. (DCTRO)
