# v0.2.1

- **A product declares how its version is written, ordered and moved.** The new `versioning:` block maps each product to a scheme, the files that hold its version, its tag and the strategy each branch decides the next version by. The schemes are `semver`, `calver` with a declared format, `number`, and `pattern`, a regular expression whose groups are the version's numbers. The strategies are `manual`, `increment` of a chosen part, `semantic` (from the commits since the latest release) and `none`. A branch overrides the product's default only where it differs, and the first pattern it matches wins. A `Version:` footer on a commit forces the next version. Nothing assumes a language, a package manager or a store: the files, the paths, the tag and the rules are the project's. A project without the block sees no change. (VRSNE, VRSNN)
- **`anchors version` shows where a product stands.** It prints the version each source holds, the latest release (the highest tag of the product reachable from HEAD, by the scheme's order), the strategy the branch resolves to and the next version with its reason. `--json` prints the same with the commits since the release classified, for a project's own script. `anchors version bump` writes the strategy's version, a raised part or a given version into every source, changing only the version's bytes, and refuses a version that does not move forward. (VRSNI)
- **New gate `version-forward`.** Declared with `scope: project`, it confronts the version the sources hold with the one at HEAD: kept or raised passes; lower, the same rank spelled differently, unreadable, or sources that disagree fail. (VRFRA)

To use `versioning:` in a project, install this binary first: an older one refuses the unknown key.
