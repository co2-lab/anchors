## Fix: `pagination-honored` reads each function's own text

Reported from MIF (`packages/backend/models/adminSources.ts`): two sister functions read through
a local `readAll` that walks every page, each with `// @no-paginate: <reason>` above its
signature. The first passed and the second stayed accused; only a second mark inside its body
made it pass. Three things were wrong, and all three are fixed:

- **The mark above a signature is that function's.** A function's body ran to the next
  declaration, so the mark above the second function was read as the first one's. The comments
  right above a declaration now belong to it, wherever it stands in the module.
- **A helper of the module that drains the cursor paginates its callers.** A function that
  reads through a function the module defines (`dialect.definition`) whose code walks the
  cursor in a loop now passes with no mark. The mark stays for what reads one page on purpose.
- **A comment is no code.** The gate read loops and cursors in comments too: the Portuguese
  `do` of "o uso do mês" counted as a loop, and functions passed as paginating by accident.
  Comments are now blanked before the code is read; the mark, a comment, is still read.

At MIF's HEAD the verdicts of the 109 files with a collection query are unchanged; the marks in
`adminSources.ts` can now be removed.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
