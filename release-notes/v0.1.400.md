# v0.1.400

- **`push_review:` — a push carries its review, and the judgments its commits reach.** Opt-in in anchors.yaml:

  ```yaml
  push_review:
    required: true          # each pushed commit is covered by a review whose verdict is ok
    file: REVIEWS.md        # where the reviews are written (the default)
    retention: 30d          # writing a review drops those older; empty keeps them all
    require_judgment: true  # each judgment gate the pushed commits reach has a verdict in the pushed map
  ```

  Whoever pushes reviews what the push sends and records it: `anchors push-review --ok "<what was validated, and how>" --by <who>`, or `--fail "<what failed>"`, with `--note` per observation. The review goes to the top of the file (when, who, verdict, commits with their patch ids, the judgment gates' answers, the text) and is committed alone. The pre-push hook runs `anchors push-review verify` with the refs the push sends. It refuses:
  - a commit no review covers;
  - a commit whose newest review failed;
  - with `require_judgment`, a commit reaching a judgment gate that has no verdict in the map the push sends.

  A review covers a commit by its hash, or by its patch id after a rebase. A commit that changes only the reviews' file and the map owes no review. `anchors guide review` has the new section "Before the push". (PSRSA, PRVLS, PRCMS, INHKN-B18, GVGDG-B32)

  **Run `anchors install-hooks --force`** to get the new pre-push; without `push_review:` it confronts nothing.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
