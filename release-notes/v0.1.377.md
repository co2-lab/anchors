## Fix: what `anchors init` seeds passes its own gates

Two defects found starting the SS monorepo:

- **In a project of several languages, the configuration `init` wrote did not load.** Each family's
  example carries the naming conventions (`set_promise`, `set_slice`), and `init` wrote them inside
  every dialect of `dialects:`, where they are the project's: the next command failed with
  `dialects.go.set_promise: the project's, not a dialect's`. They now go in `dialect:`.
- **The header guide failed the header gate.** `guides/HEADER_GUIDE.md` — and the spec guide — were
  seeded with no `@anchors` header, and a project with a guide layer had its first commit barred
  by `header-valid` on the very guide that teaches the header. Each seeded guide now opens with its
  header, under a code no file of the project holds.

And the doctor's `guide-sem-governo` on a fresh project: a seeded guide the configuration reads as a
guide now governs the layers it rules — the header guide the layers whose files carry a header, the
spec guide the specs.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
