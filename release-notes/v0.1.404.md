# v0.1.404

- **A `@contract` stamp holds across a change only to comments.** `mock-stamped` hashed the stamped block with its comments, so a rule's mark edited in a comment broke the stamp. In MIF, `// RPBTR-B02:` → `// RPBTR-B02/RPBTR-A01:` broke 81 stamps, and 122 in all, each asking a `stamp --refresh` that reconfirms nothing. When the hash no longer matches, the gate now finds the version the stamp was taken at in the module's recent history. If the block's code is the same today, with comments out and blank lines left out, the stamp holds. The comment can be edited, added at a line's end, or added on a line of its own. A change to the code still fails, as before. Stamps written before this version need nothing. Reported by MIF. (MCSTM-B24)

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
