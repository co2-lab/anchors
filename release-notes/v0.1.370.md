## Fix: a scenario the spec no longer declares stops keeping it stale

A spec's proof is kept per suite, one entry for each report that proved its scenarios. When a
scenario was renamed or removed, the suite that had proven it kept that proof under the old
code, with the spec's revision of that time. If nobody ran that suite again, it held the
spec stale indefinitely: `scenario-coverage` reported "the spec changed since the ingestion,
ingest again", and ingesting other reports did not clear it.

The case came from MIF. An aggregate visual-regression report proved `IVCHI-VR`, and the
flow behind it had been split into `IVCHI-VR-S0N`.

Each ingestion now removes from every spec's proof the scenarios whose rule the spec no
longer declares. This covers every suite, including those the ingestion did not run. A suite
left with no scenario is removed together with its revision, and the spec's proven codes and
proof revision are recomputed. The next ingestion of any report cleans up a spec in this
state.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
