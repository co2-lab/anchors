## Fix: a handle of values alone is measured through its file's own head

A component can give its handles a head of its own, as the default of the prop that carries
it, and build each handle from values only:

```tsx
function RolePicker({ testIDPrefix = ':rlpc-role' }) {
  return roles.map((r) => <Pressable testID={`${testIDPrefix}-${r.key}`} />)
}
```

`testid-consistent` treated `${testIDPrefix}-${r.key}` as a handle made of values alone, and
left the spec pending. The head is in the text, though: it is the default the `exposed`
patterns already read as a prefix (`rlpc-role-*`). When a file's patterns find a head of its
own, such a handle is now that head's and is measured through it. At MIF, the two pickers
that were pending (RolePicker, SeatTypePicker) now pass.

A handle of values alone in a file that gives no head of its own stays pending, as before.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
