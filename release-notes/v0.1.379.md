## Feature: an OpenAPI field can be another contract

A contract's field holding another contract had no type: its `Type` cell was kept as the field's
description, and the clients generated from the document typed it as anything. At SS, 19 fields
came out untyped, the items of 17 pages among them.

A `Type` cell now cites a contract by its code in backticks, as the body and the responses do:

| Input | Type |
| --- | --- |
| `items` | array of `CBRNC` |
| `rule` | `RCRUL` |

- `` `CODE` `` is a `$ref` to that contract's schema; `` array of `CODE` `` and `` `CODE`[] `` are
  an array whose `items` is that `$ref`. The field keeps what it accepts as its description.
- The cited contract is a shared schema in `components`, even when only a field cites it.
- A contract citing itself, or one citing it back, compiles: each is a reference.
- A code no spec of the project has fails the build, naming the spec and the code (`OPNAP-E03`).

A `Type` cell with no code in backticks reads as before.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
