# v0.1.405

- **New gate `symbol-exists`: a name marked as a symbol is in the project's code.** A comment or a spec marks the names it cites with `@@name`, `#name` or `$name` (dotted parts too: `#Reader.open`). The gate reads the marks in a code file's comments and in a spec's text outside its fenced blocks. Each mark is confronted against the identifiers of the map's code and test files, with their comments removed. A name that is not found fails, naming `file:line` and the name. A line that cites a name on purpose (one a dependency removed) carries `@no-symbol-check: <reason>`. Only marked names are read, so an existing project adopts the gate by marking its comments and specs; nothing unmarked is confronted. A mark glued to a word, a path or a link (`a#b`, `/x#y`, `](#section)`), a name followed by a dash (`#css-id`), an editor's `#region`/`#endregion`, a color (`#FFF`, `#C9BCFF`) and the `#` that opens a comment are not marks. It is in the catalog, informative; declare it with `blocking: true` to make it block. From MIF: a comment explained a rule by `isEvalSupported`, an option pdfjs-dist 5 removed, with every gate green.
