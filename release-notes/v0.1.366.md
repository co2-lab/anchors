## Performance: `check --all` takes half the time on a large project

A `check --all` on a clone of MIF, with the slow external tools skipped, went from 681 s to
329 s. Every verdict stayed the same: the same counts in all 109 gates, and the same 2675
findings.

Three things were redone over and over:

- **A gate's premises.** Every run of a gate on a target checked whether the configuration
  declares what the gate needs, by converting the whole configuration to YAML and back. This
  was 28% of the run. It is now done once per gate in each run.
- **The project files.** Each gate re-read its target's file, so the same file was read about
  50 times. Within a run, a file is now read once, and read again after each tool the project
  runs, since a tool may write files.
- **The shape of the map in `evidence-fresh`.** The gate rebuilt the map's edges for every
  test, three times. It now builds them once per map. Revisions are still read live, because
  the watcher updates them in place. The gate went from 65 s to under 3 s.

What remains is mostly the project's own tools. At MIF, eslint alone takes 1m43s.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
