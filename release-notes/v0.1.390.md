# v0.1.390

- **New gate `variants-proven`: a rule that names its variants is proven once per variant.** A rule that holds for several values of a discriminant — an item that is an audit or a notification — names them on its line, `@variants: audit, notification`. Each variant then asks a scenario of the rule that names it: a `@variant:<value>` tag beside the rule's tag, or a row of an outline's Examples. A variant with no scenario fails, naming the rule and the variant. (VRPRS-B01)

  ```markdown
  | `UAUDU-B02` | a tap marks the item seen @variants: audit, notification |
  | `UAUDU-E02` | a failed write propagates @variants: B02 |
  ```

  ```gherkin
  @UAUDU-B02 @variant:notification
  Scenario: tapping a notification records it in the notification log
  ```

- **A rule may follow another's variants: `@variants: B02`.** An error or an effect shared by every kind asks each of the variants of the rule it follows, so a new value asks a scenario of every follower. While one is missing, the gate diverges: the follower is "proven only without" it. (VRPRS-B02)

The gate is in the catalog as informative, and asks nothing until a rule writes `@variants:`. The spec and feature guides explain the marker. From MIF's case MIF-1S: one scenario proved the audit, the notification path shipped broken, and every gate — mutation at 100% — was green.
