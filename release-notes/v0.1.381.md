## Fix: an operation's security schemes are required together

An API spec's `## Security` table lists the schemes an operation requires. Each row compiled to an
item of its own under `security:`, and OpenAPI reads each item as an ALTERNATIVE. A client or a
gateway reading the document then accepted a call carrying any one of the schemes. At SS, a
session and an App Check, both required, compiled as either one.

The rows of a Security table now compile to one requirement holding every scheme, each with its
scopes:

```yaml
security:
  - firebaseSession: []
    appCheck: []
```

A table with one row compiles as before.
