# v0.1.388

Three fixes reported by SS while rewriting its app specs.

- **`@no-mark` without a target, on a rule's line, waives only that rule.** It used to waive every rule of the spec: one `@no-mark:` in a single table row silenced `rule-implemented` for the whole file. Written on a line that declares no rule (a paragraph, a quote), it still waives the whole spec, as before. A spec relying on a row's waiver to cover the others will now see them named. (RLIMR-B06)
- **`check --fix` no longer gives two files the same code in one run.** The codes were picked against the map read before the run, so files fixed in the same batch could each find the same code free (12 collisions over 69 headers). (FXIXX-B10)
- **A commit-message waiver `[skip-<gate>@<CODE>: why]` accepts the file's own `code:`** as well as its unit's (the spec's code, the prefix of its rules and scenarios), and `anchors guide gates <name>` says which codes it takes. (GTENG-B09)

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
