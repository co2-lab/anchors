# v0.1.394

- **`external_systems:` — the real systems the code talks to, and the suites that reach them.** A unit test proves a file against doubles, and a double of a database or an API accepts whatever it is given. MIF traced fourteen released defects to that (an index that did not exist, a condition outside the key schema, a field the API refused) and nine more to recorded responses of an API version that was gone. (EXSSA)

  ```yaml
  external_systems:
    - name: appsync
      calls: "\\bclient\\.graphql\\("
      proven_by: [integration, live]
    - name: stripe
      calls: "\\bstripe\\.[a-z]+\\.(create|update)\\("
      proven_by: [live]
      version: 2025-09-30.dahlia
      max_age: 90d
  ```

  The block is not `boundaries:`, which keeps the layers' import boundaries.

- **New gate `external-proven`:** a code file that calls a declared system needs a test of its own — derived beside it, importing it, or testing its spec's feature — that passed in one of the system's `proven_by` suite layers. `@no-external-proof: <reason>` waives it for a file. (EXPRS)
- **New gate `recording-current`:** a recorded response says where it came from, `@recorded: stripe 2025-09-30.dahlia 2026-10-02`. One of another version than the system's `version`, or of an undeclared system, fails; one older than `max_age` diverges until it is recorded again. (RCCRS)

Both gates are informative in the catalog and ask nothing until `external_systems:` is declared. The tests guide explains the two.
