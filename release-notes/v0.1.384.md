## Fix: `passed:` reads the stage's record on the sha itself

`passed: <stage>` looked for the stage's commit status only on the head of the pull request that
made the sha. A later stage of the same branch could not see a stage recorded on that same sha.
At MIF, the version pointer is meant to flip only after the production release passed on the
production sha, but it looked for that release on the review commit, which never carries it.

`passed:` now holds when the sha itself carries the stage's success. Failing that, it holds when
the head the sha was merged from carries it, as before.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
