# v0.1.392

- **A persisted data ties its writer to its reader: `writes:` and `reads:` in the header.** The writer and the reader of one record often never import each other, so nothing tied them, and each side stayed green against its own fixture while they disagreed on a field, a sign or a vocabulary — seven of the defects MIF traced to releases. A header now says what the file persists and consumes, with names the project chooses:

  ```ts
  // @anchors
  //   code: ALRTS
  //   writes: NotificationLog
  //   reads: AuditItem, NotificationLog
  ```

  The map ties each reader to every writer of its data (`reads-from`, GRBLG-B33), and a reader's test evidence holds the writer — not what the writer itself uses —, so a change to the writer's shape asks the reader's tests again through `evidence-fresh`. (RPSCR-B60, EVFRA-B16)

- **New gate `reads-written`:** a data a header reads that no header writes ties nothing, and the gate names it — a typo, or a writer that never declared itself. Informative, in the catalog; it asks nothing of a file whose header reads nothing. (RDWRS)

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
