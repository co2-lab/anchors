## Feature: a dialect per layer — a project in several languages

`dialect:` was one block per project, so a project could speak one language. A repository with
TypeScript apps and Go services had its Go code read with the TS lexicon: the patterns matched
nothing, and the gates passed it green.

A project now declares each language's lexicon once, by name, and each layer names the one its
files are written in (DESIGN-dialect-per-layer.md):

```yaml
dialect:
  gherkin_language: en
dialects:
  ts: { family: ts, ... }
  go: { family: go, ... }
layers:
  screen:  { pattern: "apps/**/*.tsx",         kind: code, dialect: ts }
  handler: { pattern: "services/**/*.go",      kind: code, dialect: go }
  go-test: { pattern: "services/**/*_test.go", kind: test, dialect: go }
```

- A file is read with its layer's dialect alone: its comments, imports, exports, tests, the
  failures it handles, the statuses it emits, the variables it reads. A file already belongs to
  one layer, and `priority` settles two matching patterns.
- Beside `dialects:`, `dialect:` holds only `gherkin_language`, `set_promise` and `set_slice`.
- With several dialects, every `code` and `test` layer names one, or the configuration does not
  load. Spec, feature and doc layers name none.
- Who imports a file is read from each importer with its own dialect. The test handle patterns
  are every dialect's together: a flow queries what a screen of another language exposes.
- A spec whose code is written in two dialects leaves the failure gates pending, naming them.
- A gate presupposing a field is pending at each dialect missing it, named there
  (`dialects.go.env_read`).
- `anchors doctor` names a layer holding files of a family its dialect's is not, with that
  family's example; its other tips speak of each dialect at its place.
- `anchors init` proposes one dialect per family it finds in the code roots, and a test layer per
  family.

A project of one language keeps its `dialect:` block, and nothing changes for it.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
