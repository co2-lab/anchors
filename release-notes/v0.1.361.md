## Fix: a broken `anchors.yaml` is an error, never an absent one

The commands that read the project's configuration loaded it and ignored the error.

An `anchors.yaml` that does not load, for example one holding a field this binary does not
know, was treated as if there were no configuration. `anchors touch` then found no comment
syntax and said every file had no header. It dated nothing and still exited 0. Measured at
MIF, a chain left 16 headers with their old date.

These commands now fail with the load error:
- `touch`, `verify`, `stamp --refresh`, `new`, `deliver`, `next`, `progress`;
- `map nav`, `guide gates`, `report`, `monitor`.

A project with no `anchors.yaml` still runs those that work without one. `anchors migrate`
is the exception: it has already rewritten files when it reads the configuration, so if it
still does not load it reports so, skips the steps that need it, and asks you to fix it and
run `migrate` again.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
