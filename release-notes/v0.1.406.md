# v0.1.406

- **A merge commit counts as the last commit of the files it changed.** The `updated-at-atual` gate and the map read each file's last commit date from one `git log --name-only`, and a merge lists no files there. A file the pre-commit dated in a merge then read the date of the commit before it: on the next commit the gate charged `updated_at (2026-11-12) ≠ last commit (2026-11-11)`, and no edit to the file could satisfy it. The log now lists, for a merge, the files it changed against every parent, as `git log -- <file>` already counted them: a header dated in the merge, a conflict resolved. A file that came unchanged from one side keeps the day of that side's commit, so a merge made without the hook (a hosting service's merge button) still passes. Reported by MIF. (GTMTG-B18)

  The first `anchors map build` after the upgrade may change the date of the nodes a past merge changed.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
