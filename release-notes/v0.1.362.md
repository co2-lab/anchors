## Fix: a derived handle that ends in its segment can be queried

A handle built on the caller's head can end in its own segment, as in `${testId}-spin`. It
was written `*-spin-*`, so a query only counted with a hyphen after the segment. `b-spin`
was never queried, and `testid-consistent` failed.

Such a handle is now `*-spin`: a consumer queries it when the segment comes after a head and
is followed by the end of the id or a hyphen, as in `b-spin`, `${id}-spin` or
`b-spin-overlay`. `b-spinner` does not count. A caller's own handle is queried through it
the same way, as in `:row-transfer-badge`. A segment followed by a value, as in
`${id}-row-${i}`, stays `*-row-*`.

Declare a closed handle as written in Test IDs: `*-spin`.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
