## Fix: a new coverage measurement replaces the old ones

A file's coverage keeps one entry per suite, and the node is as fresh as its stalest entry. A
suite measured before the file changed stayed beside a fresh measurement, and the node read stale
until that very suite ran again. At MIF, one report written a second before its file's last edit
kept a handler stale for good.

A coverage ingestion of the file's current content now removes every entry measured against
another revision, or with none: a new measurement always replaces the old ones. A report older
than the file is itself the old measurement: beside a fresh one it is dropped, and alone it is
kept with no revision, as before. With nothing measured since a change, the node stays stale.

## Feature: a file git moved keeps its evidence

A node of the map is known by its path, so a `git mv` lost every proof of a file whose content had
not changed. At MIF, 96 files moved into a package each asked for their mutation again.

A rebuild now reads the moves git sees since HEAD (`git diff -M`, staged or in the tree) and moves
each node to its new path before carrying the previous map, with the edges at it and what tests
recorded of it. The content then decides, as for any edit: the same content keeps everything, a
change that proves nothing (a header date, a comment) carries it, and a change to the code drops
it. `map build`, the commit's map, `docs build` and `recode` do this, and `keep-evidence` finds a
moved file in HEAD's map at its old path.

git decides what a move is, by content: a small file moved and much edited is a deletion and a new
file, and starts with no evidence.
