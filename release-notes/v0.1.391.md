# v0.1.391

- **New judgment gate `rule-test-coherent`: do the tests assert what the rule says?** The pair of `rule-fulfilled` on the test's side. For each rule of a spec, the judge reads the rule's text and what the tests carrying its code assert — the targets of their expect/assert, the functions, tables and fields they check — and fails a contradiction, naming the rule, the test and both sides. From MIF's MIF-1S: the rule said a tap records the item in the notification log, the test with its tag asserted `markAuditSeen`, and the tag and a green test were all any gate saw. (DFGTD-B22)

  A new project is seeded with it. An existing one opts in with one line in `gates:`:

  ```yaml
  - name: rule-test-coherent
  ```

- **The spec guide names the cases a deterministic test never meets unless asked, as variants** (`variants-proven`, v0.1.390): a matching or timing rule's refusal (`@variants: matches, does-not-match`), order (`a-first, b-first`), idempotency (`once, repeated`), concurrency (`alone, interleaved`), and a timer stopped on every exit (`completes, leaves`). Each then asks its own scenario.
