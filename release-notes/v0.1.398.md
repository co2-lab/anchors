# v0.1.398

- **The spec guide names two more cases as variants:** a screen that reads a status the backend writes, one variant per value (`@variants: active, past_due, suspended`), and a write behind an authorisation, which also refuses (`@variants: allowed, denied`), the denied scenario proving the refusal where the write happens.
- **The anchors.yaml page shows `boundaries:` as it is read** — `layer:`, a `forbid:` regular expression and `because:` — instead of a `from:`/list form the configuration never accepted, with a second example: a backend enum shown raw on a screen (`<Text>{item.kind}</Text>`) forbidden in the screen layer.

These close DESIGN-proof-gaps: of MIF's proposals, the rest is either covered by what exists (`nav-symmetric` for a promise between two screens), the project's own (eslint rules, typed label maps, `TZ` in its test runs), or left open until a peer shows a case the current gates miss.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
