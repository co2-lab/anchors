## Fixes: several `--junit` reports, one flag per module on a line, `typeof import` is a type

**`anchors ingest` takes several `--junit` reports.** Before, only the last one was ingested,
with no warning. Now each report is ingested in turn as a suite of its own, and the
`--lcov` and `--mutation` reports go with the first. A single `--suite` given with several
reports is refused: one name cannot stand for several suites.

**One flag per module on a line.** A line can hold two statements of the same module, as in
`require('x') as typeof import('x')`. The fixer wrote the flag twice
(`// @dep: CODE // @dep: CODE`). Now:

- the line takes one flag, which answers for both statements;
- `dep-declared` asks for that one flag, and `dep-honored` checks it against both statements;
- the flag is `@dep[type]:` only when every statement on the line is types only, so with the
  `require` it is a value flag;
- a line that imports two different modules still takes a flag for each.

**`typeof import('x')` is types only.** The `ts` family example now reads
`typeof import('…')` as a statement of its own, ahead of the dynamic `import('…')` that took
the same path, and its `type_import_pattern` reads it as types only. The fixer flags it
`@dep[type]:`, so it no longer counts as a value edge in a test's evidence. A project that
copied the example into its `anchors.yaml` adds two things by hand:

- the new pattern to `dialect.imports`, before the `require|import(` one:
  `\btypeof\s+import\(\s*['"](?P<path>[^'"]+)['"]\s*\)(?:\.<ident>)?`;
- the alternative `^\s*typeof\b|` at the start of `type_import_pattern`.

Then run `anchors check --fix`.

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
