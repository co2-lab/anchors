# v0.1.403

Two fixes in `anchors test`, both reported by MIF. With them, a run that proved nothing no longer reads as success.

- **The project root is written as the disk names it.** On macOS the shell's working directory may differ in case from the folder (`.../mif` for `.../MIF`). Anchors built every path from it, so `jest --findRelatedTests` got paths it did not know, found no test and exited 0, in five suites. The root now takes the disk's case, read from the system, and a part under a symbolic link keeps the link as written. (PRRPR-B04)
- **A run that proved none of its files fails.** When a suite reports a result for none of the files handed to it, the run fails, naming the count and the first path, whatever the suite's exit code. When only some files come back without a result, they are listed as unproven, as in v0.1.401. (SLCTN-B19)

Everything in the v0.1.351 notes still applies: run `anchors migrate` once, crossing format 8.
