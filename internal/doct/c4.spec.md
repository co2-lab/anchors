# C4Containers — the declared containers, each with the units that run in it, for the architecture page

> **Code**: `C4CNC`

## Overview

The central rule of the C4 model is that each level zooms into ONE box of the level above. Level
3 is the zoom of one container, not of the system: a component diagram mixing the app, the API
and the infrastructure is the failure the model exists to prevent. And a layer is not a
component: `screen` or `shared` are groupings of code in the repository, while a C4 component is
a piece with a responsibility inside a container.

The project's configuration declares which layers run in which container, and that declaration
is the bridge between the two vocabularies. This unit gives the architecture templates the
declared containers, each carrying the specs of the layers it declares, so level 3 shows the
units of that container instead of the repository's list of layers. A container that belongs to
a third party (a managed database, an external service) is still a container at level 2, but
gets no level 3: we have no components inside it, and drawing them would claim a knowledge we do
not have. A layer that no container declares is named, not hidden, because a diagram that omits
it silently claims, by absence, that it does not exist.

## Effects

| Effect | Description |
| --- | --- |
| `C4CNC-B01` | Each declared container carries the specs whose layer is one of the layers it declares, matched ignoring case and surrounding spaces, ordered by layer and then by code. |
| `C4CNC-B02` | The internal containers, the ones that get a level 3 diagram, are the declared containers minus those marked external. |
| `C4CNC-B03` | The orphan layers are the layers that have specs and that no container declares. |
| `C4CNC-B04` | Without a project configuration there are no containers and no orphan layers. |

## Domain

| Input | Accepts | Outside the domain | Who guarantees |
| --- | --- | --- | --- |
| the container declaration | the containers the configuration declares, each with a name, layers, an external flag and conversations | — | the configuration loader, which parses the declaration |
| the loaded specs | the specs the compiler loaded, each with its layer | — | the compiler (`DTCDC`), which reads them from the map |

## Invariants

| Rule | Always holds | How it is proven |
| --- | --- | --- |
| `C4CNC-I01` | Every layer that has specs is either held by a declared container or named among the orphan layers — never neither. | declares containers over some of the layers and verifies each spec layer is either in a container's units or in the orphan list |

## Constraints

| Rule | Boundary | Why |
| --- | --- | --- |
| `C4CNC-X01` | The containers are only the declared ones: none is deduced from the map or the layers. | What runs separately, and how each pair talks, is not derivable from the code map; inventing a container would draw an architecture nobody decided. |

## Errors

none — a missing configuration is answered as no containers (`C4CNC-B04`) and a layer with no container is answered as an orphan (`C4CNC-B03`); the unit reads nothing that can fail.
