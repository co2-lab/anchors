# I18nCatalog — every message a person reads, in the project's language, with a fallback that never goes blank

> **Code**: `INCTA`

## Overview

Anchors is multilingual: a project declares `lang:` in its `anchors.yaml`, and every message a person
reads comes out in that language. What is not translated is the vocabulary a person WRITES in the
configuration (gate names, labels, flags), because those are identifiers, and translating them would
break a project's configuration for a team of another language.

The supported languages are a closed list, so a project declaring a language that has no catalog is
refused at once, with the list of those that exist, instead of silently reading English. The lookup
falls back in steps: the current language, then the default language (English), then the key itself,
so a message is never blank and a missing translation names the key that is missing.

The catalog also serves the confrontation of text already on disk: a spec's section title was written
in whatever language the project had that day, so the gates can ask for a key's value in every
language, in one specific language, or, the other way round, which key and language a written title is.

## Domain

| Input | Accepts | Outside the domain | Who guarantees |
| --- | --- | --- | --- |
| the language | one of the supported codes, or empty | any other code | this unit: it is refused with the list |
| the key | a key of the catalogs | an unknown key | this unit: the key itself is returned |
| the title | a section title as written in a spec, in any case, with surrounding spaces | — | this unit normalises case and spaces |

## Effects

| Effect | Description |
| --- | --- |
| `INCTA-B01` | The supported languages are pt-BR, en and es, and the default is en. (`IsSupported`) |
| `INCTA-B02` | Setting an empty language sets the default. (`Current`) |
| `INCTA-B03` | A message is resolved in the current language, with its arguments interpolated in every language. |
| `INCTA-B04` | A key missing from the current language's catalog is resolved in the default language. |
| `INCTA-B05` | A key missing from every catalog resolves to the key itself. |
| `INCTA-B06` | The values of a key across all languages come back once each, in the order of the supported languages. (`AllTranslations`) |
| `INCTA-B07` | A key can be resolved in a given language without changing the current one, and resolves to empty text when that language lacks it. (`TIn`) |
| `INCTA-B08` | A written section title gives back the key it realises and its language, ignoring case and surrounding spaces; a title that is not in the catalogs, or an empty one, gives nothing. (`SectionKeyFor`) |

## Invariants

| Rule | Always holds | How it is proven |
| --- | --- | --- |
| `INCTA-I01` | Every supported language has a non-empty catalog, and all catalogs hold exactly the same keys. (`Keys`) | reads the keys of every supported language and compares each with the default's |

## Errors

| Code | Condition | Result | Why |
| --- | --- | --- | --- |
| `INCTA-E01` | A language outside the supported list is set. | Refused with a message that lists every supported language; the current language does not change. | The most common mistake is the code itself (`pt` for `pt-BR`); refusing without the options sends the user to the documentation. |
